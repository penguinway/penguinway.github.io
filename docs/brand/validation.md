## 验证结果

- Astro：类型及组件检查通过；生产构建通过；25 项测试通过。最终调整徽章定位后重新构建，并重跑输出资源及同步测试。
- Hugo：本机 Hugo 0.166.0 生产构建通过，使用 `--panicOnWarning`；未增加 Node.js 构建依赖。
- Hexo：临时独立站使用 Hexo 7.3.0 构建通过；没有将临时文章、数据或依赖写入主题仓库。
- 发布包：`npm pack --dry-run --ignore-scripts` 验证 301 个文件，含全部共享素材、清单及媒体来源说明，不含已删除的旧素材。
- 同步工具：预览只读、重复写入零改动、检查缺失和变更、校验源哈希、拒绝越界路径及符号链接的测试通过；失败时不执行预先收集的写入和删除。
- 资源引用：三个仓库 README 本地图片链接有效；主题代码和示例内容没有旧独有素材、旧照片或不存在 `.ico` 图标的引用。
- 自定义配置：单独执行 Hexo 配置合并，确认用户指定的 Logo 和 favicon 路径优先保留。
- 关于页徽章：390、768、1440 像素宽度下，明暗两种模式均验证图片加载且完整位于卡片内部。

[108 个浏览器场景的记录](validation.json)确认共享图片与示例媒体可加载，且没有横向页面溢出。
浏览器检查使用本机 Chrome，通过 390、768、1440 像素宽度和明暗两种模式，
检查首页、关于页、友链、404、文章和媒体示例。第三方服务在矩阵检查中隔离，
图标字体从本地读取；因此不将这些检查视为在线评论、音乐或 CDN 的可用性验证。
Astro 默认关闭赞赏，Hugo 保持原有模板；新赞赏装饰的实际悬停检查针对 Hexo。

## 已有问题

Hexo 在 1440 像素桌面尺寸打开赞赏弹层时，`#quit-box` 遮罩会挡住
`.reward-main-btn` 的指针事件。使用原仓库 HEAD 的赞赏样式重新构建临时站后，
同样复现；这不是素材替换引起的回归。390、768 像素的悬停检查通过。
桌面尺寸另行确认了新背景样式与资源地址有效；本次未调整原有遮罩或弹层交互。
